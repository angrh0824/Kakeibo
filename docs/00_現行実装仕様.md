# 家計簿 Ver2.0 現行実装仕様

最終更新: 2026-08-11

この文書は、現在このリポジトリで動作する実装を説明するものです。`01_全体処理パイプライン設計.md`〜`04_名寄せアルゴリズム設計.md`は将来構成・設計検討を含む資料であり、実装との対応関係は本書を優先します。

## 1. 現在の構成

| 層 | 現行実装 |
|---|---|
| フロントエンド | `frontend/index.html` + `frontend/css/style.css` + Vanilla JavaScript (`frontend/js/app.js`) |
| グラフ | Chart.js 4.4.3 CDN |
| バックエンド | FastAPI / Uvicorn（Python） |
| AI呼び出し | OpenRouter Chat Completions APIへの画像直接入力 |
| 現在のAIモデル | `google/gemma-4-31b-it`（`backend/.env`の`DEFAULT_AI_MODEL`） |
| データ保存 | ブラウザの`localStorage`（キー: `kakeibo.appData.v1`） |
| 永続DB | 現行画面では未使用。`DATABASE_URL`は将来のDB移行用設定 |
| 画像保存 | JPEG圧縮後、`GCS_BUCKET_NAME`設定時のみ非公開Google Cloud Storageへ保存 |

AIモデルはコード内の固定値ではなく`DEFAULT_AI_MODEL`で切り替えます。モデルを変更した場合はバックエンドを再起動してください。OpenRouterのAPIキーはブラウザへ渡さず、バックエンドの環境変数だけに置きます。

## 2. レシート読み取りフロー

1. フロントエンドで画像ファイルを最大10枚まで選択します。スマートフォンのカメラ撮影にも対応しています。
2. `POST /api/receipts/analyze`へ`multipart/form-data`で送信します。
3. バックエンドは1ファイルごとに、最大15MBを検証し、EXIFの向きを補正したJPEGへ変換します。既定値は最大辺1800px、目標1.5MB以下、JPEG品質82です。
4. 圧縮後の画像をOpenRouterへマルチモーダル入力します。1枚の画像に複数のレシートが写っている場合は、AIプロンプトでレシートごとに分離して返すよう指示しています。
5. AI応答をJSONとして解析し、`receipts`配列へ正規化します。合計、税額、税率、割引、税込単価を検証し、明細合計が印字された税込合計に合うよう必要な差額を配賦します。
6. 解析結果はレビュー画面へ渡され、ユーザーが承認したものだけが`appData.receipts`へ登録されます。承認時には元ファイル名と画像保存メタデータも保持します。
7. `GCS_BUCKET_NAME`が空の場合、画像はGCSへ送信されません。設定した場合のみ、`receipts/YYYY/MM/`配下へ非公開JPEGとして保存します。

### APIの主な応答

- `success`: 成否
- `images`: 画像単位の結果
- `receipts`: 全画像のレシートを平坦化した配列
- `total_images`, `total_receipts`: 件数
- 各レシート: `store`, `date`, `total`, `subtotal`, `tax`, `taxes`, `confidence`, `items`

現在はGCS画像を表示する認証付きAPIを実装していないため、レシート一覧の目アイコンは構造化されたレシート詳細を表示します。GCS保存を有効にしても、画像そのものが自動表示される仕様ではありません。

## 3. データ保持・バックアップ

- レシートとカテゴリはブラウザ単位の`localStorage`へ自動保存します。
- 編集、承認、破棄、商品マスタ編集のたびに保存します。
- 既存レシートの編集画面で「破棄する」を選択すると、対象レシートを`appData.receipts`から削除して保存します。
- 設定画面からJSONバックアップを書き出し、同形式のJSONを復元できます。復元前のデータは`kakeibo.appData.v1.pre-import`へ退避します。
- `localStorage`は端末・ブラウザごとに分離されます。Google Driveフォルダを共有しても、レシートデータは自動同期されません。
- 複数端末で同じデータを共有するには、共有DBまたは認証付き同期APIが別途必要です。

## 4. 月選択と画面表示

画面上部の月セレクターが持つ`currentMonth`を基準に、次の表示を切り替えます。

- ダッシュボードの支出合計、レシート枚数、品目数、カテゴリグラフ
- 月次支出推移の基準月
- レシート一覧の対象月、検索結果、ステータス絞り込み（日付は`yy/mm/dd`表示）
- モバイルのレシート一覧は日付・店舗・合計・操作に絞り、品目数・信頼度・ステータスは詳細モーダルで確認

月を変更したとき、現在表示中のページがダッシュボードならダッシュボードを、レシート一覧ならレシート一覧を再描画します。別ページを開いた場合も、その時点の選択月で初期化されます。

## 5. 操作列

### レシート一覧

- 目アイコン: 店舗、購入日時、合計、品目数、信頼度、ステータス、明細の詳細モーダル
- えんぴつアイコン: 既存レシートの編集。保存・破棄が可能

### 商品マスタ

- 目アイコン: 商品カテゴリ、平均価格、購入回数、購入履歴
- えんぴつアイコン: 商品名とカテゴリを編集し、関連する明細にも反映
- グラフアイコン: 商品の価格推移画面

## 6. 起動とデプロイ

### ローカル

```powershell
# バックエンド
cd backend
python -m uvicorn app.main:app --reload --port 8000

# 別ターミナルでフロントエンド
cd frontend
python -m http.server 5500
```

ブラウザは`http://localhost:5500`を開きます。ローカル画面は既定で`http://localhost:8000/api`を呼び出します。

### Google Cloud

- `backend/Dockerfile`でCloud Runへデプロイできます。
- `firebase.json`は`frontend`をFirebase Hostingへ配信し、`/api/**`をCloud Runサービス`kakeibo-api`へリライトする構成です。
- Cloud Runには`OPENROUTER_API_KEY`、`DEFAULT_AI_MODEL`、必要に応じて`GCS_BUCKET_NAME`とGoogle Cloud Storageの認証を設定します。
- GCSバケットは非公開を基本とし、画像閲覧機能を追加する場合は必ず認証・認可付きの署名URL発行APIを用意します。

- 複数端末間のリアルタイム同期
- GCS画像の認証付き閲覧・削除API

これらを実装する場合は、本書の現行仕様を更新してから設計書を実装に合わせて改訂します。
