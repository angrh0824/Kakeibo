# 家計簿 Ver2.0 現行実装仕様

最終更新: 2026-08-11

この文書は、現在このリポジトリとGoogle Cloud本番環境で動作する実装を説明します。`01_全体処理パイプライン設計.md`〜`04_名寄せアルゴリズム設計.md`は将来構成を含むため、現行動作については本書を優先します。

## 1. 現在の構成

| 層 | 現行実装 |
|---|---|
| フロントエンド | GitHub Pages / 静的HTML + CSS + Vanilla JavaScript |
| グラフ | Chart.js 4.4.3 CDN |
| バックエンド | Google Cloud Run / FastAPI + Uvicorn |
| 利用者認証 | Google Identity Services + Google IDトークン検証 + メール許可リスト |
| AI解析 | Cloud RunからOpenRouter Chat Completions APIへ画像入力 |
| AIモデル | `google/gemma-4-31b-it`（`DEFAULT_AI_MODEL`で変更可能） |
| 共有データ | Firestore Native mode `(default)` / 東京`asia-northeast1` |
| 画像 | 非公開Cloud Storage / 東京`asia-northeast1` |
| 端末内データ | 正本として使用しない。旧`kakeibo.appData.v1`は起動時に削除 |

OpenRouter APIキーはSecret Manager経由でCloud Runだけに渡し、ブラウザやGitHub Pagesには置きません。OAuthクライアントIDは公開識別子です。

## 2. 家族共有データ

Firestoreの`receipts`コレクションを家族全員の共通データとして使用します。各文書には次を保存します。

- 店舗、購入日時、合計、信頼度、ステータス
- 品目名、単価、数量、カテゴリ、税込調整後の明細合計
- 元ファイル名とCloud Storage画像参照
- 作成日時・更新日時
- 作成者・最終更新者のGoogleメールと表示名

商品マスタと価格推移はFirestoreの全レシート明細から画面側で集計します。商品名・カテゴリを編集すると`PATCH /api/items/master`が該当する全レシート文書をバッチ更新します。

フロントエンドは次のタイミングで共有データを再取得します。

- Googleログイン完了時
- ページ起動時
- 画面へ戻ったとき、またはタブが再表示されたとき（前回同期から15秒以上経過時）
- 画面遷移時（前回同期から15秒以上経過時）
- 設定画面の「今すぐ同期」

リアルタイムPush配信ではありません。別端末の変更をすぐ確認したい場合は「今すぐ同期」または再読み込みを使用します。

## 3. レシート読み取り・保存フロー

1. フロントで画像を最大10枚選択します。スマートフォン撮影にも対応します。
2. `POST /api/receipts/analyze`へ認証付き`multipart/form-data`で送信します。
3. バックエンドは最大15MBを検証し、EXIF補正後、最大辺1800px・目標1.5MB以下・JPEG品質82を基準に圧縮します。
4. 圧縮画像をOpenRouterへ送り、1画像内の複数レシートもレシート単位へ分離します。
5. AI応答をJSONへ正規化し、税額・税率・割引・税込合計を考慮して明細合計を印字合計へ合わせます。
6. 圧縮JPEGを非公開Cloud Storageの`receipts/YYYY/MM/`へ保存します。
7. ユーザーがレビュー画面で承認したレシートだけをFirestoreへ登録し、画像参照を結び付けます。

同じ画像から複数レシートを検出した場合、複数のFirestore文書が同じ画像を参照できます。レシート削除時は他文書から参照されていない画像だけをCloud Storageから削除します。

## 4. API

`GET /api/health`以外はGoogleログインとメール許可リスト認証が必要です。

| メソッド | パス | 用途 |
|---|---|---|
| `GET` | `/api/health` | 公開ヘルスチェック |
| `GET` | `/api/auth/me` | ログイン検証 |
| `POST` | `/api/receipts/analyze` | 最大10画像のAI解析と画像保存 |
| `GET` | `/api/receipts` | 家族共有レシート一覧 |
| `POST` | `/api/receipts` | 承認済みレシート登録 |
| `PUT` | `/api/receipts/{id}` | レシート更新 |
| `DELETE` | `/api/receipts/{id}` | レシートと未参照画像の削除 |
| `GET` | `/api/receipts/{id}/image` | 認証付き非公開画像取得 |
| `PATCH` | `/api/items/master` | 商品名・カテゴリの共有一括更新 |

## 5. Googleアカウント認証

`frontend/js/auth.js`はGoogle Identity ServicesからIDトークンを受け取り、`Authorization: Bearer <ID_TOKEN>`として送信します。トークンは`sessionStorage`へ置き、有効期限切れまたはログアウト時に削除します。

FastAPIはGoogle署名、OAuthクライアントID、有効期限、メール確認状態を検証し、`ALLOWED_USER_EMAILS`に含まれる家族だけを許可します。Gmail以外でも、そのメールアドレスがGoogleアカウントとして登録されていれば利用できます。

本番設定:

- `frontend/js/config.js`: `KAKEIBO_GOOGLE_CLIENT_ID`
- Cloud Run: `AUTH_REQUIRED=True`
- Cloud Run: `GOOGLE_OAUTH_CLIENT_ID`
- Cloud Run: `ALLOWED_USER_EMAILS`

GitHub PagesとCloud RunのURL自体はインターネットから到達可能ですが、共有データ・画像・解析APIは有効なGoogle IDトークンと許可メールがなければ`401`または`403`で拒否します。

## 6. データ保持・破棄・バックアップ

- 正本はFirestoreとCloud Storageです。ブラウザ`localStorage`は利用しません。
- 旧端末データ`kakeibo.appData.v1`と`.pre-import`は起動時に削除し、クラウドへ移行しません。
- レシート編集・商品マスタ編集は家族全員へ反映されます。
- 編集画面の「破棄する」は確認後にFirestoreから削除します。
- 設定画面から、その時点で読み込んでいる共有データをJSONで書き出せます。
- JSON復元機能は現在ありません。誤って端末バックアップでクラウド正本を上書きしないためです。
- Firestoreデータベースには削除保護を設定しています。
- Cloud Storageは公開アクセス禁止・Uniform bucket-level accessです。

## 7. 画面表示

月セレクターの`currentMonth`を基準に、ダッシュボードとレシート一覧を月別に切り替えます。日付は`yy/mm/dd`です。モバイルの一覧は日付・店舗・合計・操作を中心に表示し、品目数・信頼度・ステータスは目アイコンの詳細で確認します。

### レシート一覧の操作

- 目: 構造化詳細と、認証付きで取得した非公開レシート画像
- えんぴつ: レシート編集、共有保存、共有データからの破棄

### 商品マスタの操作

- 目: 商品カテゴリ、平均価格、購入回数、購入履歴
- えんぴつ: 商品名・カテゴリを関連レシートへ共有反映
- グラフ: 商品の価格推移
