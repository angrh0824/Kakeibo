# 家計簿 Ver2.0 現行実装仕様

最終更新: 2026-08-13

この文書は、現在このリポジトリとGoogle Cloud本番環境で動作する実装を説明します。`01_全体処理パイプライン設計.md`〜`04_名寄せアルゴリズム設計.md`は将来構成を含むため、現行動作については本書を優先します。

## 1. 現在の構成

| 層 | 現行実装 |
|---|---|
| フロントエンド | GitHub Pages / 静的HTML + CSS + Vanilla JavaScript |
| グラフ | Chart.js 4.4.3 CDN |
| バックエンド | Google Cloud Run / FastAPI + Uvicorn |
| 利用者認証 | Google Identity Services + Google IDトークン検証 + Firestore利用者状態 |
| 家計簿分離 | Googleアカウントごとの個人家計簿 + 招待メンバー共有 |

OpenRouter APIキーはSecret Manager経由でCloud Runだけに渡し、ブラウザやGitHub Pagesには置きません。OAuthクライアントIDは公開識別子です。

## 2. アカウント・承認・BAN

初めてGoogleログインした利用者は、Firestoreの`platform_users`と`signup_requests`へ`pending`状態で登録されます。承認前はレシート解析・データ・画像を利用できません。

プラットフォーム管理者には次の機能があります。

- 設定メニューの件数バッジとログイン直後のアプリ内通知で新規申請を確認
- 初回利用申請を承認
- アカウントを即時BAN
- BAN解除

BANはAPIリクエストごとに確認するため、利用中のセッションにも次の操作時から反映されます。管理者自身はBANできません。

初回申請時には`KAKEIBO_SIGNUP_REQUEST`識別ログを1回だけCloud Loggingへ記録します。Google Cloud Monitoringのログベースアラート「家計簿 - 新規利用申請」がこれを検知し、通知チャンネル`asukita824@gmail.com`へ承認画面リンク付きメールを送ります。通知間隔は最短5分、インシデント自動終了は30分です。Gmail APIや外部メール送信サービスは使用しません。アプリ内の件数バッジ・ログイン通知も併用します。

## 3. 家計簿と招待

新規承認されたアカウントには、本人がオーナーの個人家計簿を1つ自動作成します。オーナーは設定画面でGoogleアカウントのメールアドレスを指定して他の人を招待できます。

- 招待先が承認済み利用者なら、その家計簿のメンバーへ即時追加
- 未利用・承認待ちなら、管理者承認時に招待先家計簿へ追加
- 複数の家計簿へ参加している利用者は、設定画面のセレクターで切替
- 招待とメンバー解除は家計簿オーナーだけが実行可能
- プラットフォーム管理者でも、メンバーでない友人の家計簿データは閲覧不可

既存の家族3アカウントは`ALLOWED_USER_EMAILS`を移行用リストとして使い、従来データを共有する`family-main`（表示名「わが家の家計簿」）へ初回ログイン時に登録します。先頭の既存管理者アカウントがオーナーです。

## 4. データ分離と既存データ移行

レシートは次のFirestore階層へ保存します。

```text
households/{householdId}/receipts/{receiptId}
```

認証済みAPIは`X-Household-ID`を受け取り、`platform_users`のメンバー情報と照合します。選択した家計簿のメンバーでなければ`403`で拒否します。レシート一覧、登録、更新、削除、画像取得、商品マスタ更新のすべてが同じ家計簿IDに限定されます。

従来のルート`receipts/{receiptId}`は、既存家族が初回同期したときに`households/family-main/receipts`へ同じIDで冪等コピーします。移行確認後もルート文書はロールバック用として残し、新しい読み書きは家計簿配下だけを使います。

新規画像は次のCloud Storageパスへ保存します。

```text
receipts/{householdId}/YYYY/MM/{hash}-{uuid}.jpg
```

既存画像の旧パスはそのまま参照でき、再アップロードは不要です。バケットは非公開で、画像は必ず家計簿メンバー認証済みAPIを経由して取得します。

## 5. レシート読み取り・保存フロー

1. フロントで画像を最大10枚選択します。
2. `POST /api/receipts/analyze`へGoogle IDトークンと選択中の家計簿IDを付けて送信します。
3. 最大15MBを検証し、EXIF補正後、最大辺1800px・目標1.5MB以下・JPEG品質82を基準に圧縮します。
4. 圧縮画像をOpenRouterへ送り、1画像内の複数レシートもレシート単位へ分離します。
5. 税額・税率・割引・税込合計を考慮して明細合計を印字合計へ合わせます。
6. 圧縮JPEGを選択中の家計簿専用Cloud Storageパスへ保存します。
7. レビュー画面で承認したレシートだけを選択中のFirestore家計簿へ登録します。

## 7. Firestoreコレクション

- `platform_users`: Google subject、メール、状態、管理者権限、参加家計簿と役割
- `signup_requests`: 初回利用申請と承認記録
- `households`: 家計簿名、オーナー
- `household_invitations`: 招待メール、招待先家計簿、状態
- `households/{id}/receipts`: 家計簿ごとに分離したレシート
- `households/{id}/usage_events`: OpenRouterリクエストID単位の監査用AI利用量・実費
- `households/{id}/usage_periods/{YYYY-MM}`: 月次のAI・Cloud Run・Firestore・Storage利用量集計
- `households/{id}/billing_state/current`: 現在保存中の家計簿別画像容量
- `system/billing-config`: PayPay QR画像の非公開Storage参照
- `system/legacy-receipts-to-households-v1`: 既存家族データ移行完了記録

## 8. データ保持・画面表示

- 正本はFirestoreとCloud Storageです。ブラウザ`localStorage`は家計簿選択IDだけに使用し、レシート正本には使用しません。
- Google IDトークンは`sessionStorage`へ置き、有効期限切れ・ログアウト時に削除します。
- 設定画面から選択中の家計簿データをJSONで書き出せます。
- 月セレクターでダッシュボードとレシート一覧を月別に切り替え、日付は`yy/mm/dd`で表示します。
- レシート・商品マスタの編集は選択中の家計簿メンバーだけへ反映されます。
- Firestoreは削除保護あり、Cloud Storageは公開アクセス禁止・Uniform bucket-level accessです。

## 9. 家計簿別利用料金・使いすぎ防止

`BILLING_ENABLED=True`の本番環境では、レシート解析ごとにOpenRouter応答の`usage.cost`、入力・出力・推論トークン、モデル、リクエストIDを家計簿別に記録します。同じOpenRouterリクエストIDは二重計上しません。

Google Cloud分は次を家計簿別に記録し、東京リージョンの設定単価で概算します。

- Cloud Run: レシート関連APIの処理時間とリクエスト回数
- Firestore: アプリ処理から推定できる読み取り・書き込み・削除回数
- Cloud Storage: 画像アップロード・ダウンロード回数、通信量、現在の保存容量

Google Cloudの無料枠はプロジェクト全体へ適用され、家計簿へ厳密に分割できないため、画面のCloud費用は「無料枠適用前の保守的な概算」と表示します。OpenRouter分はAPI応答に含まれる実費です。円換算レートは`BILLING_USD_JPY_RATE`で管理します。

支払予定額は次の式です。

```text
管理手数料 = round(概算原価 × BILLING_MARKUP_PERCENT / 100, 2)
支払予定額 = ceil(概算原価 + 管理手数料)
```

現在の`BILLING_MARKUP_PERCENT`は100です。合計のみ1円単位へ切り上げます。決済APIとの接続は行わず、管理者が非公開Cloud Storageへ登録したPayPay加盟店QRを家計簿オーナーだけに表示します。支払い処理・入金確認は手動です。

個人向けPayPayアプリの「送る・受け取る」機能を商品・サービス代金の受領に使うことや、不特定多数へ個人用マイコードを掲示することは、PayPay公式の[加盟店向け案内](https://paypay.ne.jp/help-merchant/b0861/)と[禁止事項](https://paypay.ne.jp/help/c0442/)で禁止されています。登録できるのはPayPay加盟店向けQRだけです。加盟店契約を使わない場合は、現金や銀行振込など別の手動精算方法にしてください。

管理者は家計簿ごとに月額上限を設定できます。支払予定額と次回解析用予約額が上限へ達すると`POST /api/receipts/analyze`を`429`で停止します。既存レシートの閲覧・編集・バックアップは停止しません。初期上限は1,000円です。

計測導入前の過去利用量は遡及計上しません。
